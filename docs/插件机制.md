# DSH 插件机制笔记

来源：DSH 安装包内自带的官方作者手册与模板（`app.asar` 内
`@deepseek-ai/dsh-agent-preset/skills/cordis-plugin-development/`），
以及本机运行时的实测结果（`cordis_inspect_query`）。
版本：DSH `0.2.0-rc.2`（桌面版，profile `desktop`）。

## 1. bundle 与 Host 半区

bundle = 一个 `package.json` 里声明了 `dsh.bundle.patch` 的包。patch 用 Loader 的 YAML 语法插入插件行：

```yaml
- insert:
    - id: hello-dock          # 行 id：profile patch 靠它定位这一行（禁用/覆盖配置都用它）
      name: '@yhb/dsh-plugin-hello'   # 包名，或绝对路径 / file URL（本地开发可直连）
      # config: {}            # 前提是插件导出 Config
```

Host 半区 `index.js` 导出两种形式之一，**不要混用**：

- `export function apply(ctx, config) {}`，可另带 `export const inject = ['tools']`、`export const Config`
- 或默认导出一个 service class

用 `ctx.effect()` / `ctx.on()` 注册资源并返回清理函数；`inject` 里放**可选**服务，缺了就让插件保持未激活，而不是抛异常。可调参数放 `Config`，用户在 `cordis.patch.yml` 里改，升级不丢。

## 2. 浏览器半区

`package.json`：

```json
"exports": { ".": "./index.js", "./client": "./client.js" },
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": {
    "platform": "web",
    "immediately": true,
    "inject": ["@deepseek-ai/dsh-client-ui-conversation"]
  }
}
```

`client.js` 是**已经打包好的浏览器模块**，手写成这个格式即可（不需要 webpack/vite）：

```js
window.__ModuleLoader__.load({
  id: '@yhb/dsh-plugin-hello',      // 必须等于包名
  factory(require) {
    const React = require('react'); // React 来自浏览器的模块表，不要自己装
    return { inject: ['slots'], apply(ctx) { /* 注册槽位 */ } };
  },
});
```

- 工厂函数本身**不能有副作用**，注册全部发生在 `apply` 里。
- `dsh.client.external` 用来声明非基线运行时依赖；`dsh.client.inject` 只排序激活，不注入模块。
- 组件拿到的 props 由槽位决定（`Slots.listSubTree` 的 `standardProps`）：`conversation.composer.dock` 给的是 session 相关 hook 和 `sessionId`，**不一定有 `t`**；要用文案就自己 `inject: ['locale']` + `ctx.locale.register(NS, {zh, en})`，并对缺 `t` 做兜底。

## 3. 常用槽位（root / session 两大类）

| 槽位 | 类型 | 位置 |
|---|---|---|
| `conversation.composer.dock` | list | 输入框卡片**下方**的一条环境信息区（已有 `stats` 占用 id） |
| `conversation.input.left` / `.right` | list | 输入框工具栏左右两侧的紧凑按钮 |
| `conversation.input.dock` | list | 输入框卡片**上方**的整宽区 |
| `sidebar.panellist` | list | 侧栏全局面板图标 |
| `settings.section` | list | 设置里新增一整页（`label` + `order`） |
| `settings.plugins.tab` | list | 「内置插件」分区里新增一个标签页 |
| `plugins.detail.section` / `.badge` / `.actions` | list | 插件详情页的区块/标签/按钮 |
| `shell.overlay` | list | 最上层浮层（慎用） |

要点：`replaceRisk: none` 的槽位是**增量**的，注册进去是**并排新增**（用自己的 id）；`shadows-shipped-ui` 的槽位是**单值**的，注册等于替换官方 UI。

## 5. 插件展示元信息

- `package.json` 顶层 `icon`：相对清单目录的 SVG/PNG/JPEG/WebP，≤256 KiB（绝对路径、URL、越界、外链 symlink 都会被拒）。
- `locale/zh.json`、`locale/en.json`：`{ "meta": { "title": "...", "description": "..." } }`。
- 缺失字段回退到 `package.json` 的 `name` / `description`；元信息格式错误只产生诊断，不阻止安装与激活。
- 需要在 `exports` 与 `files` 里放行 `./package.json`、`./locale/*.json`（读取器直接从磁盘拿这两个路径）。

## 6. 安装、启用、观察

### 6.0 浏览器冻结基座：客户端半区只能 require 这 9 个说明符（实测）

官方规则说"不要 require Harness 客户端包"、又提过一个 `dsh.client.external`。实测把边界定死了：
`dsh-client-modules` 的 `require` 在**未命中 seed 表**时**直接 throw**
（源码原文 `client-modules: require("${spec}") missed the module table — not a platform seed word, …`），
而 seed 表由**外壳**在 boot 时注入。它在 `@deepseek-ai/dsh-web-frontend/dist/assets/index-*.js` 里（函数 `rM()`），**只有 9 项**：

```js
{ react, "react/jsx-runtime", "react-dom", "react-dom/client",
  "@deepseek-ai/cordis",
  "@deepseek-ai/dsh-client-store",          // ✅
  "@deepseek-ai/dsh-client-ui-slots",       // ✅
  "@deepseek-ai/dsh-client-ui-primitives",  // ✅
  "@deepseek-ai/dsh-client-ui-dockkit" }
```

推论：
- **require 这 9 个是安全的**（`dsh-client-store`、`ui-primitives` 常被第三方插件用，属于合法用法）。
- **require 其他任何 Harness 客户端包都会抛错** → 客户端模块加载失败 → 因为 `immediately: true` 属启动批次，
  表现就是**渲染进程启动失败**（用户旧环境真崩过的那种）。这类包要动态依赖，得写进 `dsh.client.external`。
- `dsh.client.inject` **只排序激活、不授权模块请求**——两者别混。
- 复现方法：`node tools/asar-tool.mjs extract <app.asar> dsh/node_modules/@deepseek-ai/dsh-web-frontend/dist/assets/index-*.js out.js`，然后搜 `react/jsx-runtime`。

> **实测踩坑（2026-10-12）：`inject` 里写一个**外壳不存在**的 id，会让条目永不激活——落在启动批次里就等于整页起不来。**
> 现象：装完一个侧栏余额插件后重启 DSH 桌面端，弹崩溃报告 `Error: web boot: 1 entry did not activate`
> / `dsh-sidebar-balance: failed`（崩溃日志在 `%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*-web-boot.log`）。
> 桌面端的自动恢复随后把 profile 的 `dsh.profile.bundles` 削回 `["@deepseek-ai/dsh-base","@deepseek-ai/dsh-web-app"]`，
> `cordis.patch.yml` 也丢了 `agent-default-model` / `agent-preset-registry`、`ui-settings` 被置 `enabled: false`
> ——原 patch 备份留在同目录 `cordis.patch.yml.bak-*`，可整段还原（`package.json` 的 bundles 手写回来即可）。
> 该插件写的是 `"inject": ["@deepseek-ai/dsh-client-runtime"]`，而外壳 `index-5SrrfWpU.js`（633 KB）里
> **没有 `dsh-client-runtime` 这个字符串**（`dsh-client-store` / `dsh-client-ui-primitives` / `ui-slots` / `ui-dockkit` 都有）。
> **结论：写 `inject` 之前，先在外壳产物里 grep 一遍那个 id；宁可用 `[]`。**

> **实测踩坑（2026-10-11）：用 `link:` 外链安装的插件，不要 import 随 DSH 提供的包。**
> 我在 preflight 插件里 `import { defineTool } from '@deepseek-ai/dsh-tools'`，装上去直接
> `application: failed`，诊断是 `yhb-preflight (@yhb/dsh-plugin-preflight): failed to import`；
> 补上 `peerDependencies: { "@deepseek-ai/dsh-tools": ">=0.2.0-rc.2" }` 再重组**仍然失败**；
> 把 import 去掉、改成手写 JSON Schema 之后**一次就 applied**。
> 官方 app-boot 文档里的“链接目录”规则说：profile 链接到树外目录时，只有**该目录 package.json 里
> 声明的 peer 包名**才会落到运行时表——但实测在热重组路径上并没有生效。
> **结论：外链开发的插件要么零依赖（只 import `node:*` 和自己的相对文件），要么把包真正装进
> profile（非 link）再 import。** hello 插件之所以一次成功，就是因为它什么都没 import。

- `plugin_manager` 的 `install_bundle`（`target` = 插件目录绝对路径）负责装包 + 写 profile + 选入 bundle。**不要**手写 profile 的 `package.json` / `cordis.patch.yml`，不要在 profile 目录跑 pnpm。
- **改完代码要让它重新生效**：`set_bundle false` → `set_bundle true` 会强制一次重组（`changed: true` 才代表真的重组了；`changed: false` 拿到的是上一次的结论，容易误判）。
- `list_bundles` / `list_plugins` 拿准确 id；`set_bundle` / `set_plugin` 开关；`remove_bundle` 卸载。
- 保存状态与激活结果是两件事：`failed` 需要诊断，`overridden` 表示被更高优先级的层覆盖，`restart-required` 表示还没生效。
- 浏览器同步失败会单独显示在设置的插件列表里；**换掉已安装包的代码需要重启**才能加载新的 JS 模块版本（改代码后重装 ≠ 立即生效）。

## 7. 失败会怎样（决定“崩不崩”）

| 失败模式 | optional 条目 | required 条目 |
|---|---|---|
| 模块 import 失败 / 同步 `apply()` 抛异常 / 配置校验失败 / `!!js` 求值抛错 | 警告，继续跑 | 终止启动 |
| 异步 `apply()` 抛异常 | 结算后警告，继续 | 结算后终止启动 |
| 注入的服务不可用 | 等待依赖，继续 | 终止启动 |
| 脱离 `apply()` 的异步任务未处理 rejection | **致命：释放应用并非零退出** | 同左 |
| 同步回调（定时器、流 `data` 监听）未捕获异常 | **致命：释放应用并非零退出** | 同左 |
| 客户端组件抛异常 | 该槽位条目崩溃（控制台 `slot entry crashed in '<slot>'`），整页不受影响 | —— |

Web 的 required 集合包含 `modules` 与 `connection`。所以：**Host 半区保持最小、把重活放进 effect 并清理**，是插件不把 DSH 搞崩的关键。
